# 검증 범위와 남은 한계

2026-10-21. S0~S6 Qwen 기반 결과의 해석 범위다.

| 항목 | 확인한 사실과 제한 | 후속 검증 |
|---|---|---|
| 데이터 | 모니터링과 로그는 합성 예시다. 실제 운영 로그·배포 이력·인과관계를 검증하지 않았다. 시각이 다른 근거는 상관관계 확정에 사용하지 않는다. | 실제 연동 시 별도 승인된 데이터로 평가 |
| RAG | 작은 런북 6종과 고정 E5 임베딩을 사용한다. S2 별도 held-out 알려진 유형 6개 중 top1 4개, unknown 3개 모두 거부. 혼동과 보류가 남는다. | 코퍼스·사람 검토 사례 확장 |
| multi 조사 | 출처별 성공·부분 실패를 구분하지만 MCP 세션 잠금 때문에 실제 Tool/Resource 접근은 직렬이다. 별도 fake 실험의 속도 차이를 실모델 개선으로 일반화하지 않는다. | 실제 동시 부하·출처별 시간 비교 |
| 요약의 형식·출처 | S6 단순 메모 12턴에서 Qwen 8B가 원문에 없는 메모_2 등의 근거 ID를 생성해 검증에서 거부됐다. 최근 10개 원문 fallback은 동작했지만 초기 이름은 회상하지 못했다(HTTP/SSE 모두). 기존 S4 고정 대화는 양쪽 모두 요약 저장·회상에 성공했다. | 실패 사례를 보존해 후속 모델 비교에 포함 |
| 요약의 의미 | 출처 ID 검사를 통과한 JSON도 사실을 누락·왜곡할 수 있다. 후속 probe에서 요약 저장 뒤에도 이름 회상에 실패했다. 형식 성공을 기억 품질 성공으로 계산하지 않는다. | 사람 검토 및 정정·철회·가설 유지 사례 확대 |
| 메모리 비용 | S4 고정 이력의 사실 회수는 recent 0/5 → summary 5/5였지만 총 토큰은 1247 → 3090으로 증가했다. 항상 토큰이 줄거나 빨라지는 것은 아니다. | 같은 대화 길이·모델·실행 조건 비교 |
| 동시성·저장 | 동일 프로세스의 같은 thread는 직렬, 다른 프로세스는 요약 version CAS로 덮어쓰기 방지. 다중 worker 전체 요청 순서는 보장하지 않는다. FinalAnswer 직전 commit 후 전송 유실 시 DB에 완료 대화가 남을 수 있다. | 다중 worker 및 완료 경계 실패 실험 |
| 스트림 취소 | ASGI 2.4에서 토큰 대기 중 종료와 프록시 전파 결함을 S6에서 수정했다. 이미 시작된 동기 호출·외부 추론 서버의 연산 중단까지 보장하는 것은 아니다. | 다양한 네트워크·서버 구현에서 반복 |
| Judge | Qwen Judge는 허용 외 조회 차이를 CPU 4/4 점수로 구분하지 못했고 일부 해설도 과장했다. 사람 검토 사례는 독립 4개뿐이며 세부 숫자 점수는 사람이 정한 정답이 아니다. | 같은 저장 답변에 OpenAI Judge 교차 평가 |
| 과거 기록 | S2 과거 1행은 원본 CPU 91% 계측 후 서비스 입력을 10%로 바꾼 측정 래퍼 문제로 unscored다. 임의 보정하거나 0점으로 처리하지 않았다. 같은 조건 재생의 S2는 정상 평가했다. | 원본 보존, 신뢰 가능한 신규 계측 |
| 재현과 수치 | 버전 재생은 현재 설치 의존성을 공통 사용했으며 당시 전체 환경 복원은 아니다. 단계별 서로 다른 모델·fixture·질문의 지연을 단일 성능 개선율로 합치지 않는다. 단일 사례 smoke는 부하 시험이 아니다. | 고정 환경과 반복 표본으로 추가 평가 |
| 비용 | 로컬 Ollama API 청구액은 $0이나 전력·연산 비용은 측정하지 않았다. 서비스 USD는 토큰×가정 단가의 예시이며 실제 청구액과 다르다. S6 SSE 전체 사용량 합계는 미계측(N/A)이다. | OpenAI 모델·호출 수·비용 상한 확정 후 측정 |

OpenAI 검증은 아직 실행하지 않았다. 이후 같은 입력·출처·rubric에서 Judge만 교체하는 실험과, 서비스 답변 생성 모델도 교체하는 실험을 분리한다. Qwen 결과를 덮어쓰지 않으며 외부로 보낼 데이터와 호출 예산을 먼저 확정한다.
