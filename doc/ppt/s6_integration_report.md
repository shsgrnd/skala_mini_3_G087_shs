# S6 통합 검증 결과 — Qwen 기반

> **기록 시점 안내:** 아래는 2026-10-21 Qwen 검증 시점의 결과와 후속 계획을 보존한 문서다. 이후 OpenAI 교차 검증·반복 측정·응답 취소 수정을 완료했다. 최신 결과는 [모델 교차 검증](model_validation.md)과 [루트 보고서](../../README.md)를 참조한다.

2026-10-21. 기준 커밋은 S5 `2d0fdc7`이며 S6의 SSE 수정은 이 보고서 작성 시 미커밋 작업 트리에 있다. OpenAI 추가 검증은 아직 실행하지 않았다.

## 결과와 완료 범위

서비스의 HTTP/SSE·MCP·RAG·multi·summary 조합을 실제 TCP에서 검증하고 스트림 중단 결함을 수정했다. 전체 회귀와 fake 통합은 통과했다. **Qwen 장기 기억의 새 단순 메모 사례는 실패했으며, 이 품질 한계는 해결 완료로 표시하지 않는다.** 기존 S4 고정 대화에서는 정상 요약·회상이 재현됐다.

## 실행 조건과 변경

- 로컬 Ollama `qwen3:8b`를 fast/quality에 모두 사용했다. 기본 0.6B 모델의 품질과 같은 결과로 취급하지 않는다.
- v2 / strict / rag / multi / summary, 기존 로컬 E5 인덱스, 실제 ops/docs stdio MCP를 사용했다. 모니터링 난수와 현재 시각은 실제 구현 그대로이며 데이터는 합성이다.
- 전용 DB와 localhost 테스트 포트를 사용했다. 사용자 8100·8600 서버·.env·session.db는 변경하지 않았다. 사용자 서버는 keyword이므로 전체 조합은 별도 서버에서 검증했다.
- API·웹 프록시에 공통 `agent/streaming.py`를 적용했다. ASGI 2.4에서도 disconnect를 전송과 병행 수신하고 asyncio 취소를 한 번 전달한 뒤 작업 종료를 기다린다. 응답 iterator와 내부 그래프 스트림도 명시적으로 닫는다.
- 새 코드의 책임·선택 이유·자원 정리 경계를 한국어 주석으로 기록했다. 서비스 단위 테스트만 공개하고 보고서 전용 코드·원시 결과는 로컬에 유지한다.

수정 전 API/프록시 ASGI 2.4 단위 테스트 2개가 TimeoutError로 실패했다. 첫 처리에서는 반복 취소와 yield 지점 정리가 LangGraph 하위 작업까지 정리하지 못하는 문제가 실제 TCP에 남았다. async generator 종료와 단일 취소/완료 대기를 적용한 뒤 단위·TCP·실제 Qwen 토큰 중단을 확인했다. 최종 리뷰에서 생성기 I/O 오류까지 연결 종료로 삼던 범위를 소켓 send 경계로 좁혔다. 생성기 OSError 전파 실패를 RED로 재현하고 소켓 종료와 구분하는 테스트 2개를 추가했다. 최초 실제 모델 중단 기록은 고정 안내문에서 끊겨 모델 생성 중 취소의 증거로 쓸 수 없었다. 해당 기록을 보존하고 다음 실제 모델 출력 조각 `1`을 받은 뒤 끊어 다시 확인했다.

이미 완료된 요청의 저장을 되돌리거나 외부 추론 서버의 연산 중단까지 보장하지 않는다.

## 장기 기억에서 확인한 모델 한계

12턴의 첫 질문에만 이름을 넣고 이후는 단순 메모로 채운 새 사례에서 회상에 실패했다. 같은 사례를 다시 실행해 Qwen이 원문에 없는 `메모_2` 등의 observed_evidence_ids를 생성하는 것을 확인했다. 서비스는 이를 거부하고 최근 원문으로 fallback했으며 요약 checkpoint를 전진시키지 않았다. 안전한 실패 처리는 통과했지만 초기 이름 회상은 실패다.

별도 후속 probe에서는 저장 가능한 요약이 만들어져도 이름을 회상하지 못했다. JSON 형식 검사와 출처 ID 검사는 의미 보존을 완전히 보장하지 않는다. 반면 기존 S4의 이름·서비스·기준값·시각·결정을 포함한 고정 이력은 실제 라우팅을 유지한 이번 HTTP/SSE에서도 이름 회상과 요약 저장에 성공했다. 성공 사례로 실패 사례를 대체하지 않고 둘 다 보존했다.

## 단계별 비교

S5에서 실제 소스 스냅샷을 같은 fake 모델·고정 stdio MCP·현재 의존성으로 재생한 결과다. 과거 실모델 raw와 합산하지 않는다.

| 단계 | 허용 외 조회/운영 2사례 | S0 대비 변화 | CPU 출처 확보 | 이름 회상(fake) | CPU Judge | 수치 지지 |
|---|---|---|---|---|---|---|
| S0 | 2/2 | +0%p | 0.667 | 1/1 | 4 | 3/3 |
| S1 | 0/2 | -100%p | 0.667 | 1/1 | 4 | 2/2 |
| S2 | 0/2 | -100%p | 0.667 | 1/1 | 4 | 2/2 |
| S3 | 0/2 | -100%p | 1.000 | 1/1 | 4 | 3/3 |
| S4 | 0/2 | -100%p | 1.000 | 1/1 | 4 | 3/3 |
| S5/final | 0/2 | -100%p | 1.000 | 1/1 | 4 | 3/3 |

S0 2/2 → S1 이후 0/2는 100%p 감소(상대 100% 감소)이며 작은 합성 2사례의 정책 검사다. 출처 확보는 monitoring/synthetic_log/runbook 3종 중 반환된 종류 수로, 내용의 진실성이나 실제 운영 로그 조회를 뜻하지 않는다.

단계별 CPU Judge는 모두 4점이고 fake 이름 회상은 모두 1/1이다. 이를 개선 증거로 해석하지 않는다. S4와 S5/final은 같은 서비스 소스다. 지연은 해당 재생에서 기록하지 않아 N/A이고, 독립 소규모 분류 실험의 top1을 이 표에 이식하지 않았다.

CSV의 estimated_cost_usd는 fake 토큰 추정과 가정 단가를 사용한 서비스 비용 예시이며 Judge 비용을 포함하지 않는다. 실제 로컬 API 청구액은 0이다.

## 지연·비용과 재현 범위

S6 Qwen CPU 단일 요청은 HTTP 약 21.66초, SSE 완료 약 16.18초였다. cold/warm·질문·추론 길이가 섞이는 smoke이며 두 endpoint의 우열이나 p95·부하 성능을 주장하지 않는다. 동일 조건 단계 재생에는 지연 기록이 없어 비교 CSV의 p50/p95는 N/A다.

로컬 API 청구액은 $0이다. 서비스 metadata의 cost_usd는 가정 단가로 계산한 예시이며 실제 과금이 아니다. S6의 전체 SSE 토큰/비용은 미계측이므로 N/A로 남긴다. S5 최종 Judge의 23회·29297토큰도 S6 서비스 사용량에 합산하지 않는다.
